# 学習・評価の要件（ドラフト）— 8 kHz NSS

作成: 2026-10-23 / issue #11 / 状態: **確定（2026-10-23、ユーザー承認）**。

`docs/handover.md` §5 の未決 3（補助ゲート）と 4（学習設定）を詰めた案。

**用途（2026-10-23 ユーザー回答）**: NSS は**オフライン**で、制御ゲインの最適化と、制振性能の事前評価に使う。実機の制御器の中では動かさない。このため (d) は「実時間で動くか」でなく「シミュレーションが速いか」に読み替える（§4）。データと入出力の定義は `docs/requirements_8khz.md`（確定済み）に従う。

## 2. 学習データの扱い

| 項目 | 案 | 理由 |
|---|---|---|
| `nearLimit` 942 件 | **含める**（除外しない） | 全体の 0.007%、接触ではない自由運動で、学習への影響は無視できる。除外すると `hold_+060` の端の運動だけ欠ける |
| 入力 | `X`（4 列）＝ `[sin q, cos q, dq/5.236, tau/860.4]`、さらに入力ごとに train の平均・標準偏差で標準化 | `requirements_8khz.md` §3 |
| 出力の標準化 | (A) 純 NN: `Y_scaled`（ddq/141.38）を**そのまま目標**にする。(B) 残差型: 残差 `Y − a_phys` を **train の残差の標準偏差（0.519 rad/s²）で割る** | 接触を除いたので外れ値が無い。固定定数なら (A)(B) で単位がそろう |
| (B) の入力 | `X`（4 列）＋ `a_phys / 141.38`（1 列）の 5 列。最後の層を 0 で初期化（開始時点は解析モデルそのもの） | フォーク元の `ResidualNSM` と同じ考え方（そこでは 6 列：解析モデルの Δq, Δdq） |
| 損失 | 標準化した目標の MSE（Huber・二重損失は使わない） | 同上 |
| 更新式 | `dq1 = dq + Δt·ddq`、`q1 = q + Δt·dq`（オイラー） | 決定事項 2 |

## 3. モデルと学習設定

| 項目 | 案 | 理由 |
|---|---|---|
| 構造 | (A) 純 NN `ddq = f(x)`、(B) 残差型 `ddq = a_phys + f(x)` | 決定事項 2 |
| 層構成 | 全結合、SiLU、**深さ 3** | フォーク元と同じ |
| 幅 | **{64, 128, 256} を比べる**（スクリーニング） | 幅は精度（a)(b)(c) とスループット (d) のトレードオフで選ぶ |
| 最適化 | Adam、学習率 2e-3 → 1e-5（ウォームアップ付きコサイン）、バッチ 4096、重み減衰なし | フォーク元と同じ（変える根拠が無い） |
| エポック | スクリーニング **5 エポック**、本学習 **20 エポック**（約 65,000 ステップ。フォーク元の 40 エポックは約 19,000 ステップ） | 8 kHz は隣接サンプルがほぼ重複するため、エポック数でなくステップ数で見る |
| 早期終了 | val 損失が **5 エポック**改善しなければ終了 | 接触が無く val の揺れが小さい（フォーク元は接触の外れ値で val が揺れ、既定の 8 では早すぎる打ち切りが起きた） |
| シード | スクリーニング 1 本、本学習 **3 シード** | 分散を見るため。モデルが小さいので 3 本で現実的 |
| 実行 | `nohup` でバックグラウンド。ワーカー 1 本ずつ直列（メモリ 13 GB のため） | 学習データの読み込みで約 2〜4 GB |

**所要時間の見積もり**（直列。1 エポックは幅 256 で 4.6 分、幅 128 で 1.4 分、幅 64 は未測定だが 1.4 分より短い）

| 段階 | 内容 | 時間 |
|---|---|---|
| スクリーニング | {A, B} × 幅 {64, 128, 256} × 5 エポック × 1 シード | 約 1.2 時間（幅 256 が 23 分 × 2 で大半） |
| 本学習 | 勝った幅 {A, B} × 20 エポック × 3 シード | 幅 128 なら約 3 時間（28 分 × 6 本）、幅 256 なら約 9 時間 |

## 4. 評価ゲート

主ゲート (c) は決定済み。(a)(b)(d) は、実測の基準線（解析モデル）から次の値を提案する。評価は val でなく **test と benchmark** で行う。

| ゲート | しきい値（案） | 測り方 | 根拠 |
|---|---|---|---|
| **(c) PTP 閉ループ（主）** | **12 本とも発散せず、真値との θ RMSE ≤ 0.1°**（決定） | 8 kHz の PD＋FF（wn = 30 rad/s、ζ = 1）にモデルを接続し、`benchmark` の参照軌道を全長追従。真値の閉ループ記録と比較 | 決定事項 3 |
| (a) 1 ステップ ddq RMSE | **test: A・B とも ≤ 解析モデル × 1.0**（benchmark は参考値。#16 で確定） | `Y` と予測の差の RMS [rad/s²]。基準線は test 0.531、benchmark 0.147 | 1.0 倍以内なら (c) の最悪は 0.058° 以下（感度実験）。PTP は解析モデルが既に良く、倍率が大きく出るため参考値 |
| (b) 開ループ θ RMSE（窓） | **4,000 ステップ（0.5 秒）で A・B とも ≤ 0.4°**（8,000 ステップは参考値。#16 で確定） | 窓の開始間隔 2,000。記録トルクを再生して自己回帰。解析モデルも同条件で測る | 0.4° 以下なら (c) は 0.085° 以下。8,000 ステップは θ=0 まわりの不安定性で (c) と無関係に増幅される |
| (d) シミュレーション速度 | **バッチ並列のロールアウトで ≥ 145,000 ステップ/s**（Simscape の約 1,450 ステップ/s の 100 倍）。ウォームアップ後、10 回のうち**最速**で判定（共有マシンの割り込みを除く。中央値・全回も記録）。1 サンプル推論の時間は参考値として記録 | 多数のゲイン候補を同時に進めるロールアウト（バッチ 1,024）で、ステップ/s を測る。Simscape 8 kHz は実時間の 5〜6 倍かかる（約 1,450 ステップ/s）。ゲイン最適化では候補を並べて走らせるので、実時間の保証でなく**スループット**が価値になる。暫定値で、測定後に見直す |

(b) は補助、(a)(d) は幅の選択に使う。(c) が通らなければ、(a)(b) が通っても不合格とする。

スクリーニング（#15、`docs/screening_8khz.md`）と本学習（#16、`docs/main_training_8khz.md`）の結果を受けた改訂。(a)(b) の限界は感度実験で (c) との関係から確定（2026-10-24、ユーザー承認）。

## 5. 実装の範囲（承認後）

`python/` のフォーク元コードは 1 kHz の遷移（Δq, Δdq の 2 出力、接触対応）を前提にしているため、**8 kHz 用に新しく書く**（フォーク元の構成は流用しない）。

1. データ読み込み（`/<split>/{X,X_raw,Y,Y_scaled,a_phys,...}`）
2. モデル (A) / (B)（出力 1 列）、学習スクリプト（ステップ数ベースの学習率スケジュール）
3. 評価: 1 ステップ誤差、8,000 ステップ窓、PTP 閉ループ（8 kHz）、ロールアウトのスループット
4. 単体テスト（形状、(B) の開始時点が解析モデルに一致、閉ループ追従など）

## 6. 決定事項（2026-10-23 承認）

1. `nearLimit` 942 件は**含める**（フラグのみ。除外しない）
2. 幅 {64, 128, 256}、スクリーニング 5 エポック、本学習 20 エポック × 3 シード
3. ゲート (d) は、用途がオフラインのため**スループット**（暫定 145,000 ステップ/s 以上）に変更。値は測定後に見直す
4. ゲート (a)(b) の倍率は §4 のとおり

## 7. スコープ外（次のスコープに委ねる）

用途（オフラインのゲイン最適化と制振性能の事前評価）から出た 2 つの論点は、今回は扱わない。

1. **制振性能の評価**: 真値プラントは剛体 1 軸で、減速機やリンクの弾性・共振を持たない。NSS は共振・振動を再現できない。評価するには、弾性（ばね・ダンパ）を入れた真値プラントの作成と、データの取り直し（生成だけで約 4 時間）が要る。
2. **ゲイン違いの再現性 (c2)**: (c) は wn = 30 rad/s・ζ = 1 の PD 1 種類での追従のみ。ゲインを振ったときの閉ループ応答とコストの順位が真値と合うかは、次のステップで評価する。案は、wn ∈ {15, 30, 60} rad/s × ζ ∈ {0.7, 1, 1.5} の 9 組で PTP の真値を生成して比べる（真値生成は 1 組あたり約 10 分、計約 1.5 時間）。

したがって、今回の NSS が保証するのは「wn = 30 rad/s・ζ = 1 の PD を使った剛体 J2 の閉ループ追従」までで、ゲイン最適化や制振評価にそのまま使える保証はない。

## 8. 実装（issue #13）

```bash
.venv/bin/python python/train_nss.py --model A --width 128 --run A_w128_s0        # 20 エポック、バッチ 4096、patience 5
.venv/bin/python python/train_nss.py --model B --width 128 --epochs 5 --run B_w128_screen
.venv/bin/python python/evaluate_nss.py --run A_w128_s0 --report-dir reports/issue-N/A_w128_s0   # ゲート (a)〜(d) を判定
.venv/bin/python -m unittest discover -s python/tests                              # 単体テスト（39 件、約 20 秒）
```
- `python/nss8k/`（`data.py` `physics.py` `model.py` `evaluate_lib.py`）、`python/train_nss.py`、`python/evaluate_nss.py`。フォーク元の `python/j2nsm`（1 kHz）は残してあるが 8 kHz では使わない。
- 閉ループの参照は HDF5 の `qref`（倍精度）を数値微分して作る（速度・加速度）。Python の PD＋FF を真値の状態に当てると、記録トルクとの差は RMS 0.016 N·m（制御器の再現を確認）。
- 評価の所要時間: 全体で約 3 分（窓 100 本の動作確認時。窓を全件にすると増える）。学習は幅 64 で 30 万行 3 エポックが約 10 秒。
